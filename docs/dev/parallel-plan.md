# 可选的多人协作方案

默认按根目录 `AGENTS.md` 单任务直接开发。本文件只在用户明确要求多人并行或沿用已发布任务卡时使用；不构成普通开发的派发、分支、worktree 或门禁前置条件。

## 何时启用

- 两个以上写入者同时开发时，为各自安排独立 worktree，并协调可能重叠的文件。不要让两个写入者共用同一 checkout，也不要覆盖他人的未提交修改。
- 若任务涉及共享接口，先约定兼容性和调用方迁移；可在同一个工作范围内完成跨模块实现，无须人为拆成 core/retrieval/cleaning 多个包。
- 需要审计分工时，可以记录目标、起点、修改范围、验收和测试结果。任务卡、`ownership.json`、角色分支和独立 handoff 均为可选工具；旧任务继续按原任务卡交付。
- 已发布任务卡若选择使用 `tools/collab_gate.py package` 或旧 `check --role`，须遵守该卡约定，不通过改候选任务卡、检查器或测试发现规则伪造通过。工具的通过结果只适用于对应代码与基线。

## 验证与交接

日常只跑相关测试；公共契约、状态机、权限、幂等、计数、持久化、依赖和检查规则变更以及阶段发布，按 `AGENTS.md` 跑完整回归。纯文档检查差异格式即可。真实依赖不可用时标记 `NOT_RUN`，不得把模拟测试当作真实联测。

开发进度及明细记录到 `docs/dev/progress.md`；大型并行工作可使用 `docs/dev/handoffs/`。更新实际命令、结果、未验证项和下一步。运行环境、端口及测试账本按需隔离；DSH 命令显式指定独立 `DSH_HOME`。

历史任务卡、交接和门禁代码保留用于追溯，不自动迁移或中断现有任务。创建其他任务/代理、提交、推送、合并及外部系统操作仍遵循用户授权。
