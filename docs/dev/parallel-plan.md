# 工作包协作流程

2026-10-24 用户授权简化流程。新工作包使用下述模式；旧角色任务卡和 check 命令继续兼容。v1.9 业务安全与验收要求不变。

## 四步完成一个工作包

1. 总控一次性明确目标、主责、基线、独立 worktree/分支、精确文件范围、验收与测试策略，发布任务卡。无需用户逐个批准常规技术文件；超出授权的业务决策与外部操作仍需确认。
2. 开发者在独立工作区完成接口、实现、调用方和测试。单个工作包可经授权跨 core/retrieval/cleaning；角色不再是永久文件围栏。并行任务不得同时编辑同一 checkout。
3. 执行范围检查及按风险选择的测试，写本包独立交接。不把定向通过写成全量通过，不把 mock 写成真实联测。
4. 总控审查并按授权集成，汇总进度。阶段集成/发布执行完整回归，同一代码状态的有效证据可以复用。

## 分配和权限

任务卡从可信基线读取，必须由总控发布；执行窗口不得自行修改任务卡扩大范围或降级测试。新分支使用 codex/<工作包>，不能与另一活跃包共用。ownership.json 仅为新包提供模块主责参考与仓库允许路径边界，旧模式仍按其固定分支/角色范围检查。

同一包内兼容接口与实现一起提交审查；破坏兼容性、影响其他活跃工作包或改动其在用文件时才先协调。变更请求写清原因、接口示例、影响方与迁移方式，不能复制另一套模型避开接口约束。

新增范围由总控更新并发布新的授权基线；普通包禁止修改自身/他人任务卡、责任表、根或嵌套 AGENTS、协作检查器及其防绕过测试。此类治理变更必须单独获得用户授权、隔离实施、验证反例，不能用新规则给自身宣称旧规则认证。

## 新任务卡

任务卡位置 docs/dev/tasks/<工作包>.json。字段：
- role：integration/core/retrieval/cleaning，仅主责标签。
- branch：本包唯一 codex/ 分支。
- source_base：起始提交完整 SHA，必须是发布基线的祖先。
- files：精确相对文件清单，可跨模块；不接受目录、通配、路径穿越、符号链接或子模块。
- acceptance：具体可检验结果及适用规格验收编号。
- handoff：docs/dev/handoffs/<任务卡文件名去掉.json>.md，必须列入 files，保证每包独立。
- tests：mode、targets、reason。mode 为 full / targeted / docs。targeted 的 targets 是非空 unittest 名称列表，例如 tests.test_catalog_config；其他模式 targets 为 []。reason 说明风险和覆盖依据。

命令：

```bash
python3 tools/collab_gate.py package --base <发布基线SHA> --task docs/dev/tasks/<工作包>.json
```

检查所有已提交、暂存、未暂存和未跟踪差异；旧基线不包含新卡时拒绝，不能回退 baseline 绕过。可信检查器由总控/CI选择，不是由候选代码自动建立信任。脚本不是沙箱，也不能自动识别另一个窗口正在写相同目录，写入者交接仍要明确。

## 按风险验证

- 日常开发：相关测试；没有测试则补充，无法验证如实记风险。
- 低风险包：定向测试。无效名称、空测试集、失败均不能算通过。
- 高风险包：完整回归。包括公共契约/模型、状态机、权限/幂等、计数/补数、持久化/格式、依赖/构建和检查规则。脚本保守匹配部分路径；总控还必须判断语义风险，不能因文件名不命中就降级。
- 纯非执行文档：格式检查，代码测试 NOT_RUN，并记录理由。契约、规则、配置的语义变化不能冒充文档豁免。
- 阶段集成与发布：完整回归；真实试点另需真实依赖、重启恢复、权限与业务验收证据。复用证据必须对应同一代码状态和测试环境，不能复用变更前的结果。
- 旧 check 命令保持全量回归。切换新模式须先由总控发布新卡，不自动重写运行中的旧工作包。

## 进度与运行隔离

各包维护自己的 handoff，总控独占更新 progress.md。开工、关键里程碑、阻塞/恢复、交付及时更新；活跃最长 30 分钟。状态使用 IN_PROGRESS/BLOCKED/READY_FOR_REVIEW/ACCEPTED；未跑 NOT_RUN，执行中 RUNNING。只有经总控审查的结果标 ACCEPTED。无活动不要求后台定时更新，不为此创建自动化。

环境、端口、输出与测试账本独立，DSH_HOME 显式设置。不得迁移、覆盖或清理真实业务数据来方便测试。不覆盖未提交改动；混合改动先确认归属，不整树 stash/复制/重置。

## 旧任务与迁移

旧任务仍可按原卡顺序交付；要并行时重新分配独立包/分支/交接。无关已发布提交导致范围检查失败时，审查提交后重新指定可信基线，不能直接无条件使用 HEAD。当前 R06 草稿和其他窗口文件保持原位，本规则升级不自动启动、迁移或中断任务。

本地规则不能代替服务端保护。正式协作应由受保护目标分支提供可信检查器和分配信息，配置必需检查与审查；当前不声称已配置远端保护。
