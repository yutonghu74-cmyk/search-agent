# 窗口启动任务说明

使用前：A 完成基线与公共契约；用户创建独立任务/worktree。以下占位符必须替换，不得原样当作已分派任务。一次只分派一个可验收切片，不要求单窗口一次实现全部规格。

## A：总控窗口

```text
你是本项目总控 A。先读 AGENTS.md、docs/dev/parallel-plan.md 和 v1.9 规格书。
先审查首次 Git 基线准备情况，再对齐本轮公共契约、固定样例与契约测试。
为 B/C/D 编写任务卡，明确角色、基线完整 SHA、文件范围、具体切片、验收项和依赖。
不要把 P0 现有接口当成完整 v1.9，不默认安装 PostgreSQL，不重写 DJ plan_flow。
本轮允许动作：<用户明确授权的动作>。
未授权时不要创建其他任务、提交、推送、合并或安排自动后台执行。
审查交付时先运行可信版本的角色检查，再审查代码与业务验收证据；逐个集成并回归。
```

## B/C/D：开发窗口通用任务卡

```text
你负责角色 <core|retrieval|cleaning>，仅在当前独立 worktree 工作。
先读取 AGENTS.md、docs/dev/parallel-plan.md、docs/dev/ownership.json，
以及 v1.9 规格书相关章节和下述验收项。
基线完整 SHA：<BASE_SHA>
分支：<ownership.json 对应分支>
本轮切片：<具体功能，不要写“实现全部后端”>
已冻结契约与示例：<文件及版本>
验收项与测试：<规格编号、输入、预期结果、测试位置>
允许动作：本职责内编辑与本地测试；<其他用户明确授权动作>
只修改本角色允许路径；新增共享接口先在本角色交接文件提案，等待 A 发布新基线。
在范围内持续实现→测试→修复；缺少外部依赖或需要扩权时记录阻塞，不伪造通过。
交付前运行 python3 tools/collab_gate.py check --role <角色> --base <BASE_SHA>。
按 docs/dev/handoff-template.md 写 docs/dev/handoffs/<角色>.md。
停止条件：本轮验收满足且检查通过；或需要契约决策/外部资料/新授权。
不要自动合并，不修改责任表或检查器以绕过失败，不把模拟联测标成真实通过。
```

建议首批切片（待 A 冻结契约后才可执行）：

- B：草稿→确认创建的原子与幂等边界，扩展现有测试；后续切片再接计数/补数。
- C：检索端口的确定性 fake 和分页/权限/映射失败契约测试，再接真实驱动。
- D：一个固定配方的 plan_flow 适配验证，输出逐素材判定与业务标识映射；记录真实运行证据。
