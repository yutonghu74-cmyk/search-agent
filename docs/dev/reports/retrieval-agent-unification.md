# 统一检索Agent：规划、确认与执行

生成检索词和确认后检索由同一个`RetrievalAgent`负责。原`RetrievalTermsAgent`及`ConfirmedTermsRetrievalAgent`作为内部阶段适配器保留；不是把两个名称改成相同名称，也不要求一个模型请求一直运行。

```mermaid
flowchart LR
    D[对话服务保存结构化需求] --> P[检索Agent生成方案]
    P --> W[等待发起人确认]
    W --> R[同一检索Agent恢复检索]
    R --> C[候选按已确认策略进入清洗]
```

## 实现与接口

- [统一服务入口](../../../src/dsh_retrieval/retrieval_agent.py)持有规划队列及原检索执行适配器。HTTP、查询/派发和结果读取使用相同Agent身份`retrieval-agent@1`。
- 规划仍通过`POST/GET .../dialogue-sessions/{session}/retrieval-agent/terms`完成。成功后phase为`waiting_confirmation`，携带规划作业ID、词表摘要和需求版本；没有创建正式任务或派发素材检索。
- 新增`POST .../retrieval-agent/terms/{job}/confirm`，需要发起人的幂等键及`action=confirm`、`dialogue_version`、`plan_digest`和完整`proposal`。用户实际确认当前完整方案后才创建业务草稿/任务，原检索派发账本继续执行。
- 确认之后原规划查询地址仍可读取，返回对应task、执行作业和阶段；执行回执也带原规划ID与摘要，不重新扩词或丢失血缘。后续版本只引用与当前已确认词表摘要匹配的规划；无匹配记录时不冒称沿用旧规划。
- 前端保存并恢复规划确认信息，直接调用新确认入口。方案或执行设置变化时要求重新生成/确认，不静默降级到另一条创建任务路径。旧页面/历史草稿的原建任务入口与旧执行契约保持兼容。
- 已有召回分析及词表调整能力继续作为本Agent的内部能力；已确认任务的后续修改仍经过现有版本确认门禁，不自动放宽来源、预算或启动补数。

## 持久化与确认边界

使用规划账本中的`retrieval_agent_confirmations`关联租户、发起人、项目、会话、规划作业、请求摘要、词表摘要、业务草稿确认参数和task。它是关联/确认记录，不是平行task、batch或run模型。

确认前核对：当前会话版本、最新生成的规划、原始需求、数量、完整词表及配额、模型绑定、素材库权限和当前执行策略。其他用户、旧需求、同版本下被重新生成取代的旧词表、过期模型或来源权限均不得确认。

重复点击以规划ID派生原业务幂等键，不依赖每次浏览器生成的新键。跨账本中断时复用已保存的草稿确认参数及原task；任务账本已经提交但关联回执丢失，也可以找回原任务。若用户随后修改了需求，恢复旧确认不能归档或覆盖新需求。

权限、素材检索、清洗、预算、去重和有效数量仍归原业务服务。新入口不新增整批候选确认，原自动/手动候选策略保持有效。结果是否可用及有效数量以原业务结果接口为准。

## 验证与交付

- 新增生命周期、发起人隔离、策略/模型失效、同版本重新生成、并发确认、重开账本、跨账本确认丢失及保留新需求的定向测试；Node行为测试核对新确认入口不会另建不相关草稿。
- 最终175项关联定向测试通过（79.568s），覆盖统一生命周期、词表队列、旧确认执行、Chat行为、召回分析、窗口和派发。DSH环境缺Pillow导致过一次导入失败，原日志保留；使用已有CLIP环境完整发现同组相关测试通过，未安装依赖、未删减测试。
- 真实GLM页面请求“狗吃饭、兔子睡觉，各2张”生成待确认方案，确认前正式任务数为0；刷新后通过新确认入口继续原规划，仅创建1个任务。规划、确认回执和执行结果的Agent身份及规划作业/摘要一致；真实重复确认仍是同一任务和执行作业。
- 实际9次检索/9条原始命中、4候选自动进入现有Qwen清洗，1次派发、约68.59秒完成；正式通过1、淘汰3、缺口3，未发布或补数，不代表达到4张目标或认证视觉质量。
- 确认后原会话归档，原规划地址仍可读取执行状态；隔离服务重启后规划数、任务数、关联及模型审计数前后一致，没有重新扩词或派发。刷新正式页面另核对节点和有效数量。回执在本机忽略目录`var/unified-retrieval-20261126/live/`。
- 公共OpenAPI补充统一身份、规划血缘及确认入口，复用原DraftBody/TaskSummary。原DraftBody的node_modes曾只写manual，本次修正文档以表达后端已实现的自动检索/清洗/补数模式；业务校验未放宽。三个OpenAPI及其229个本地引用解析通过，差异格式检查通过。未运行完整回归，未宣称生产多实例或真实内网验收。
