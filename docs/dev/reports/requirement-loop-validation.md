# 三类图片需求闭环验证

验证日期：2026-11-26。范围：本机隔离环境、合成诉求和既有公开测试素材。

使用用户指定的 Qwen-3.8-27B 补验后，三类各20张的需求理解、词表生成、刷新恢复、确认后真实CLIP检索、自动清洗及结果计数的执行闭环已跑通。首批9个候选中模型判定2个通过、6个淘汰、1个待复核，距60张目标仍差58张。预览抽查发现通过项中存在动作证据不足的疑似误判，图片语义质量尚未验收；本记录不代表收集到60张或通过真实内网验收。

## 本次修复

- 模型首次保存或替换主体时，必须保存结构化类别和场景；字段与原文证据逐项校验。单一类别补充明确张数可直接保存，未明确的类别配额不由总数推算。
- 明确失败显示可重试状态，沿用原命令标识；网络结果未知时只核对。换模型后仅在原命令已明确失败时释放原命令并重新发送，不重发运行中或未知操作。
- 清除已入账命令和已保存草稿的“新建Chat”标记，刷新能恢复同一对话与待确认词表。
- 新 @2 委托在首批查询窗口提交后固定候选并交接现有清洗，不在input_only下先翻完所有游标。执行器与候选确认账本使用同一版本边界，旧 @1 继续沿用原行为。
- 新清洗操作使用已确认原文与类别作用域的确定性指令，防止模型二次整理增添排除条件；历史操作仍使用原冻结指令。运行中检查点不再被称为已完成。

## 回归与复现边界

开发语义检查修正了两个误判：类别名称可以包含原文场景；局部修改的scene可以只保留变化动作，由稳定类别补足主体。同时增加错误动作、错误配额、重复类别、条件泄漏和场景对象丢失的负例，保留数量、作用范围和字段证据校验。

累计清洗用例在HEAD原检索实现下也存在“首批只有1项却要求至少2项”的前提错误。该用例改用批量4，使现有渐进召回首批取2项，保留全部累计计数与血缘断言；随后暴露并修复账本未识别已有“备用来源延后”策略的问题。未跳过或删除失败测试，未缩小发现范围。
