# 任务浏览性能改造方案

- 日期：2026-11-07
- 状态：实施中；节点分页、候选缓存上限、事务内任务事件及当前历史账本副本对照已落地；线上切换与整体性能验收尚未完成。
- 范围：生产总览、历史 Chat、五个节点详情、素材预览、实时更新。
- 原则：保留现有业务语义、发起人权限、幂等和版本隔离；使用 SQLite 持久化查询层，不引入必装的新数据库。

## 1. 目标与现状

让打开一个任务的读取成本主要取决于当前页面需要显示的内容，不随全库历史任务和候选数量线性增长。任务内部的结果、步骤和素材均按页读取，避免因单任务持续补数而无限增加首屏成本。

当前瓶颈包括：

| 优先级 | 瓶颈 | 影响 |
| --- | --- | --- |
| P0 | 页面读取反序列化大 JSON 账本 | 查看单个任务也付出读取整份账本的成本 |
| P0 | 读取结果时重新构建累计结果血缘 | 补数、反馈和历史结果增加后，重复计算与验证成本增长 |
| P0 | 单张清洗预览读取全量步骤，并重复读取已发布候选 | 图片展示产生请求放大，文字显示后仍长时间等图 |
| P0 | 总览以三个并发遍历全部任务的进度 | 请求量随历史任务数量增长，与详情请求竞争资源 |
| P0 | 节点详情串行读取任务、进度、版本并重复校验 | 轻量节点也被完整任务加载链路阻塞 |
| P1 | 清洗摘要先生成完整结果再去掉逐图字段 | 返回内容变小，但主要计算成本仍存在 |
| P1 | SSE、侧栏和候选轮询重复读取 | 同一个任务在多个入口重复生成快照 |
| P1 | SSE 使用全库变更时钟 | 无关任务写入也可能触发当前任务快照重建 |
| P1 | Chat 初始化串行等待配置与历史列表 | 模型设置等非首屏必需数据阻挡历史内容恢复 |
| P2 | 候选窗口连续补读此前加载的分页 | 恢复位置时产生大量请求，DOM 数量持续增长 |
| P2 | ZIP 下载重复完整读取和验证，前端等待完整 Blob | 大包增加等待时间与内存占用 |

本地历史任务的单次抽样：任务列表约 10 ms、会话列表约 13 ms、候选第一页 24 条约 1.02 s、交付详情约 0.71 s、单张约 261 KB 的清洗预览约 3.27 s。先前抽样中，全任务进度约 1.86 s，而历史版本读取约 5 ms。

以上为诊断样本，不是 P95、压力测试或生产环境结论。

## 2. 总体架构

```text
业务执行 / 用户反馈 / 补数完成
                |
                v
同一 SQLite 事务
  ├─ 更新业务账本
  ├─ 写入版本化页面查询数据
  ├─ 更新当前版本指针
  └─ 写入所属任务的变化事件
                |
                v
页面按任务、版本、节点和游标读取
  ├─ 摘要
  ├─ 结果或步骤的一页数据
  └─ 单个素材的授权绑定
```

业务账本继续保存完整依据。页面查询层是可以从业务账本重建的持久化投影，不独立决定业务状态、有效数量或补数策略。大 JSON 暂时保留作业务依据和审计，逐步退出页面读取路径。

完整结果计算和完整性校验在发布、迁移及恢复等路径完成。日常读取保留当前身份、项目权限、版本、素材归属和必要完整性检查，通过索引定位数据，不重复计算整个历史结果。不得以性能优化为由跳过撤权检查或把未知判定视为通过。

## 3. 第一批：持久化查询层与单图读取

### 3.1 数据结构

以下为建议表名，实施时与已有仓储模型核对，避免复制平行公共模型。

| 查询表 | 内容 | 主要用途 |
| --- | --- | --- |
| `task_read_heads` | 当前 revision、generation、task_version、输出版本和事件水位 | 当前版本选择与校验 |
| `task_read_summaries` | 标题、任务状态、五节点摘要、目标数、有效数和缺口 | 总览、Chat、任务顶部 |
| `task_node_snapshots` | 节点状态、计数、当前输出引用 | 五节点详情 |
| `result_read_items` | 素材分类、稳定排序、组归属、短原因和素材版本 | 结果分类与分页 |
| `cleaning_step_summaries` | 步骤状态、输入/输出版本和分类计数 | 清洗步骤摘要 |
| `cleaning_step_items` | 步骤内逐图判定和证据引用 | 清洗步骤分页 |
| `task_asset_bindings` | 素材所属结果或步骤、媒体引用、摘要和授权范围 | 单图预览 |

所有查询记录具有明确的租户、项目、任务及版本归属；按用途建立任务、输出版本、分类、步骤和稳定排序索引。当前版本指针与不可变历史输出分开保存。已有候选分页存储能够复用的继续复用。

### 3.2 写入与一致性

1. 在结果发布、人工复核、用户排除、补数完成和 revision 变更等业务事务内同步更新查询数据。
2. 运行中 checkpoint 的步骤计数与输出水位同样进入查询层，不能只有完成态快、运行态仍整本读取。
3. 查询数据写入失败则事务整体回滚，不允许业务已更新而页面摘要滞后。
4. 旧运行回传通过现有任务、revision、generation 校验后才可更新当前指针；查询层不得绕开业务版本栅栏。
5. 结果分类和计数直接采用业务层确认的计算结果，查询层不另算一套有效数量。
6. 查询层记录格式版本及来源版本/摘要；缺失、版本不匹配或完整性异常时明确失败并进入修复流程，不静默返回旧数据。

### 3.3 单图预览

- 以任务、当前输出版本、candidate_id 和 asset_version 直接定位授权绑定。
- 取消先遍历所有步骤再查找单图的路径；在读取前后通过轻量版本校验保留并发撤权和版本变化语义。
- 列表读取尺寸受控的缩略图，大图在用户点击后读取。
- 缩略图按内容摘要和转换规格复用，每次请求仍验证当前权限，不能把历史授权当作永久访问许可。
- 前端限制图片并发，并取消离开页面后不再需要的请求。

第一批交付重点：结果查询与单图授权不再解析全库计划账本，不再逐次重建累计结果。

## 4. 第二批：有界读取接口

| 接口用途 | 返回内容 | 约束 |
| --- | --- | --- |
| 任务总览列表 | 一页任务摘要与五节点状态 | 服务端分页，不逐任务调用 progress |
| 任务首屏 | 当前摘要、版本和节点摘要 | 不返回逐图证据和全部历史版本 |
| 指定节点详情 | 当前节点内容与输出引用 | 仅查询所选节点，大清单分页 |
| 结果分页 | 固定结果版本、分类的一页素材 | 数据库执行分页，不全量加载后切片 |
| 清洗步骤摘要 | 步骤状态和计数 | 不构造逐图结果 |
| 清洗步骤分页 | 指定步骤、分类的一页判定 | 游标绑定步骤及输出版本 |
| 单图预览 | 当前获准读取的图片 | 直接查询素材归属和授权绑定 |

每个响应携带统一版本标识。后续分页绑定首次读取的输出版本；若当前版本发生变化，沿用已有冲突语义，引导读取新版本，禁止拼接两个版本的数据。

采用稳定排序的游标分页，并设置服务端页大小上限。接口兼容调整和调用方一起交付，现有权限、游标篡改检查与版本隔离语义不降低。

## 5. 第三批：前端加载与任务事件

### 5.1 生产总览与历史 Chat

- 总览一次请求一页摘要，取消三个 worker 遍历所有任务进度的逻辑。
- 历史 Chat 先显示对话与任务摘要，再独立加载结果第一页。
- 模型设置、素材库和运行版本说明不阻挡历史内容展示；只在相关操作确实依赖时等待。
- 历史列表服务端分页，避免长期全量拉取多套列表后在浏览器合并。

### 5.2 五个节点

- 进入任务读取一次首屏；切换节点仅请求该节点的数据。
- 同任务、同输出版本的已加载节点复用现有内容；版本变化后只失效受影响节点。
- 切换时取消旧请求，并检查响应所属任务、节点及版本，避免过期响应覆盖当前页面。
- 清洗先显示步骤计数，展开后再读取一页素材和证据。
- 检索、补数轮次和交付清单采用有界分页，避免把大清单直接渲染为整个 DOM。

### 5.3 候选窗口与实时更新

- 恢复浏览位置时只读取当前位置附近的数据，不连续补齐此前全部页面。
- 大列表使用虚拟列表或等效的有界渲染方案，控制 DOM 和图片内存数量。
- 在业务事务内记录按任务划分的事件；事件只包含变化类别、版本及引用，不携带图片或大段证据。
- SSE 初次连接和重连读取已有事件，不重建全量业务快照。
- 任务 A 的更新不引起任务 B 的快照计算。
- 同一任务共用更新调度，合并在途请求；收到事件后只刷新受影响部分。
- 轮询作为断线恢复手段，事件过期时读取当前轻量快照恢复水位。
- 已结束且没有新变更的任务停止周期性重读；连接恢复仍检查权限和当前版本。

## 6. 第四批：历史迁移与部署切换

1. 使用隔离的账本副本建立查询层，迁移程序记录格式版本、处理进度和来源水位，支持幂等重跑与中断续跑。
2. 逐任务核对 revision、generation、task_version、结果摘要、各分类数量、组配额、缺口和素材归属；覆盖旧格式、历史人工裁决与多轮补数。
3. 对照新旧读取结果，差异必须定位和处理；迁移验证不加入每次页面请求。
4. 活跃写入期间不得用旧迁移快照覆盖新投影。初次实际切换采用维护窗口暂停写入，完成最终迁移与核对后恢复。
5. 实际账本切换前备份，验证迁移、启动和旧读取回退的兼容性；保留明确的切换配置，不在失败时悄悄回退慢路径。
6. 先在独立端口验证，再切换 8096。保留现有身份及游标签名配置，检查浏览器实际加载版本。
7. 回退时恢复已验证的读取配置；只有明确确认备份后的业务写入如何保全，才可考虑恢复数据库备份，禁止直接覆盖新增业务数据。

当前隔离副本迁移入口：`PYTHONPATH=src python3.13 tools/migrate_task_asset_bindings.py <source.sqlite> <new-copy.sqlite>`。目标文件必须不存在；工具在隔离副本中建立任务摘要、结果分类、清洗步骤、素材绑定、交付/补数分页和写侧事件，执行 SQLite 完整性、行数及逐项业务对照。旁置 `.migration.json` 记录来源摘要、阶段和验证计数；失败保留 `.migrating`，用同一命令加 `--resume` 续跑。来源变化则拒绝续跑或发布，要求新的目标文件。续跑粒度为备份、投影、验证阶段，投影事务中断会重新执行该阶段；不自动切换服务账本。

页面请求不得承担首次全量迁移或查询层重建。

## 7. 验收与测试

### 7.1 性能目标

以下为本批本地验收目标；最终测量、采样口径与适用范围见本文末尾收尾记录。

| 场景 | 目标 |
| --- | --- |
| 总览第一页、任务摘要 | API P95 ≤ 200 ms |
| 历史 Chat 文字首屏 | 点击到可读 P95 ≤ 300 ms |
| 扩词等轻量节点详情 | 点击到可读 P95 ≤ 300 ms |
| 结果、清洗第一页 | API P95 ≤ 500 ms |
| 已生成缩略图 | 单图响应 P95 ≤ 300 ms |
| 全库历史数据扩大十倍 | 同一任务固定页读取耗时增长不超过 20% |

记录样本量、P50/P95、响应字节数、请求数量、错误率和数据规模。冷启动、首次生成缩略图、暖读取及多页面并发分别报告，不能用单次最快响应代替 P95。

2026-11-07 新增可重复的隔离合成微基准：`PYTHONPATH=src:tests .venv-clip/bin/python tools/benchmark_task_read_summary.py --samples 100`。Darwin/arm64、Python 3.13.3，暖系统缓存，每次读取新建 SQLite 连接，每页 20 条，各路径采样 100 次。100 / 1,000 个任务下，新列表读取 P50 为 0.509 / 0.552 ms，P95 为 0.970 / 0.934 ms；兼容旧路径 P50 为 3.760 / 31.314 ms，P95 为 4.951 / 36.301 ms。数据库大小分别为 647,168 / 6,217,728 字节。该测量只覆盖合成任务的服务层与存储读取，不覆盖 HTTP、浏览器、图片、并发或实际历史数据，不据此标记本节整体目标达成。

除了扩大无关历史数据，还需扩大单任务素材数和补数轮次，确认分页读取与单图授权不重新扫描全部输出。结构性检查应确认热路径没有进入全库 JSON 反序列化和累计结果重建函数。

### 7.2 语义回归

- 业务写入和查询层更新共同提交、共同回滚；重复请求幂等。
- 重启后读取结果、步骤、版本指针和事件水位一致。
- 旧运行不能覆盖新版本；结果和步骤分页不能混用版本。
- 用户、租户、项目隔离，以及素材撤权后的拒绝读取。
- 人工裁决、用户排除、分组配额、去重、补数累计数量与旧业务结果一致。
- 迁移中断恢复、重复迁移、旧格式兼容、来源摘要不匹配和投影损坏明确失败。
- 快速切换任务或节点后无过期响应覆盖；断线恢复不重复大量加载。

当前连续开发阶段运行与改动直接相关的定向回归。完整回归在用户明确要求或进入阶段集成/发布验收时执行。本地结果不等于真实内网联测或 v1.9 全量验收。

## 8. 后续工作与交付记录

ZIP 下载另设切片：评估不可变包的持久校验证据、当前授权复验、流式传输和前端下载方式，减少重复全包读取及 Blob 内存占用；不在本批无依据取消完整性检查。

业务账本写入仍存在整份 JSON 序列化和长写事务的增长风险。页面读取改造完成后，以独立压测评估写入耗时和锁等待，再决定是否按任务拆分权威写模型。查询层不宣称解决全部写入性能问题。

每批交付记录：修改范围、定向测试结果、同一数据下的前后耗时、迁移/回退证据、尚未覆盖的边界。推进情况更新到 `docs/dev/progress.md`。

实施顺序：结果查询层与单图授权 → 有界读取接口 → 总览、Chat、五节点和事件接入 → 历史迁移与 8096 切换。

本方案按批次实施。当前已接入任务摘要、结果与步骤分页、素材绑定、交付清单和补数轮次分页。候选每展示页 60 项、每窗口最多 180 条命中元数据、最多保留 3 个任务窗口；更早内容以游标重新读取，来源合并明确限定在当前缓存窗口。生产检索页最多缓存 3 个接口页（72 条命中）。事务内写入任务事件，首连及重连重放已有事件，不再依赖浏览请求创建通知；保留旧账本兼容观察路径。当前 8096 的历史账本隔离副本已完成全部 5 个任务对照。历史 Chat 列表分页、缓存/刷新优化、8096 切换及本地浏览器/并发验收现已完成；最终证据与边界见本文末尾收尾记录。


### 2026-11-07 续做：候选窗口有界展示

- 候选和四类结果的缩略图网格最多挂载 60 个候选，支持已读取内容的前后翻页；末页存在服务端游标时，下一页按需读取。已有自动追加继续更新数据，不推走当前页或大图。
- 离页时断开图片观察器、取消请求并回收 Blob URL；退出大图同样清理媒体。恢复游标按当前展示页或选中素材定位，避免浏览前页却保存最后读取页；增量 changes 游标不会误作普通分页游标保存。
- 定向验证：`test_candidate_window`、`test_chat_ui` 共 60 项通过；Node DOM 适配测试追加 100 页 / 6,000 个候选，验证网格上限、翻页回看、图片资源释放、首末页按钮、筛选及恢复游标。该测试不是实际浏览器性能测量。
- 仍保留已加载元数据以维护原有来源聚合；这次只限制 DOM 和图片，不宣称整个候选浏览器内存恒定。未重启 8096、迁移实际账本或执行完整回归。


### 2026-11-07 续做：节点分页、写侧事件、缓存与历史副本验证
