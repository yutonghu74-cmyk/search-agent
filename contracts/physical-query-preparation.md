# 授权物理查询准备

依据 v1.9 §6.1—6.3，PhysicalQueryPreparer 是仅供后端调用的准备服务，不提供客户端可直接提交向量/过滤表达式的入口。

输入为调用者、任务标识、预期 RetrievalScope、逻辑预览摘要、分支标识、选中的 binding_id、epoch、batch_size 和后端授权版本。读取当前确认方案重新编译分支，拒绝旧作用域、摘要不符和未知分支。项目权限及原有 validate_scope 同时约束创建人、生命周期和运行状态。

CatalogRepository 必须先按权限过滤再做目录匹配；准备服务再次验证 discover/search 权限，不把授权错误当空结果。只有目录中的唯一匹配绑定可以使用；拒绝跨库映射、歧义和缺失。当前不自动猜选库，不把目录描述送给外部模型。

TextQueryCapability 为服务端静态注册，绑定完整 IndexBinding（索引版本、编码器版本、维度和度量），显式声明 image 的文本查询链路、受控过滤模板和批次上限。它不是网络输入，部署方应先验证实际编码链路再注册；不因为向量维度相同就认为兼容。无注册拒绝，不回退到任意模型。当前 source_constraints 非空时拒绝，直到有可验证的过滤编译器，不能静默丢弃来源条件。

编码由已有 EmbeddingProvider 执行。返回值须为 QueryVector，原 validate_plan 检查编码器、维度和有限数值；编码后复验任务作用域、项目与库权限。准备结果是 PreparedQuery，内部复用 RetrievalPlan/SearchRequest，并保留分支标识、查询指纹、逻辑摘要与准备摘要。计划标识绑定作用域、分支、索引、向量、过滤模板和批次参数；同样输入稳定，改变执行参数改变标识。

本服务无账本写入、确认、预留分页或 search 调用，不创建 run，不授予执行权限。现有账本仅有一个当前计划；不能把多个准备结果依次确认冒充同时批准多个分支。多分支原子批准/调度需 core 契约扩展。真实适配器仍须在执行时复验授权与索引状态，准备结果不是永久访问凭据。

本包为合成依赖测试，不代表真实目录、Embedding、Milvus 或内网联测通过；HTTP/Chat 尚未装配真实物理准备入口。
